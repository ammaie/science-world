# إصدار V11 – تطوير مركز الطالب والملف الشخصي

## ما أُضيف إلى ملفات المشروع
- تحديث صفحة الملف الشخصي الحالية بدل إنشاء صفحة مكررة.
- عرض بيانات الحساب المتاحة، حالة توثيق البريد، الصف والفرع ورقم الطالب عند توفرها.
- ربط حقول الملف الشخصي بجدول `profiles` وحفظ الاسم في بيانات Supabase Auth.
- عرض حالة الاشتراك اعتمادًا على خدمة الاشتراكات الموجودة.
- توفير روابط عملية للأقسام الموجودة في المشروع مع تحسين الحفظ وتسجيل الخروج.
- تحويل صفحة التقدم من نص تجريبي إلى قراءة محاولات الاختبار المتاحة من `exam_attempts` مع حالات فارغة وأخطاء واضحة.
- إضافة SQL توسعة لجدول الملف الشخصي ورقم طالب وسياسات ملكية البيانات.

## ميزات مطلوبة لم تُنفذ بعد في هذا الإصدار
هذه الميزات لا تُعرض على أنها مكتملة حتى يتم توفير الخدمات والجداول والإعدادات اللازمة:
- رفع الصورة الشخصية فعليًا عبر Supabase Storage.
- إحصائيات الدروس والأسئلة وساعات الدراسة وسلسلة الالتزام، لعدم توفر مصادر بيانات مؤكدة متكاملة لها.
- نقاط وشارات ومستويات مع احتساب موثوق على الخادم.
- سجل عمليات الاشتراك والتجديد إذا لم يكن جدول السجل موجودًا ومتكاملًا.
- المحادثات المحفوظة والجدول الدراسي إذا لم تكن خدماتهما موجودة.
- تغيير كلمة المرور وإدارة الجلسات وحذف الحساب عبر تدفق خادمي آمن ومكتمل.
- تفضيلات الإشعارات والصوت والمظهر واللغة إذا لم تكن مرتبطة بالتخزين الدائم.
- تقرير أسبوعي PDF ومشاركة الإنجازات مع إخفاء البيانات الخاصة.
- قسم «رحلتي نحو البكالوريا» يعتمد على قياسات تقدم حقيقية لكل مادة.

## مطلوب قبل التشغيل
1. راجع `supabase/profile_enhancements.sql` ثم نفّذه في مشروع Supabase المقصود.
2. تحقق من أن أسماء أعمدة `profiles` وسياسات RLS متوافقة مع مخطط المشروع الفعلي.
3. راجع مسارات GoRouter التي تستدعيها صفحة الملف الشخصي.
4. شغّل `flutter pub get` ثم `flutter analyze` و`flutter test` وابنِ APK.

## حالة التحقق
لم يتم تشغيل Flutter Analyze أو الاختبارات أو بناء APK أثناء إنشاء هذا الأرشيف. لذلك لا يُعد V11 إصدارًا مبنيًا أو مختبرًا.
